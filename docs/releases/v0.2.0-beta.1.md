# CodeLeveler v0.2.0-beta.1

The first public beta. A **local-first coding agent runtime**: a persistent
execution engine that inspects, edits, runs and verifies real repositories,
with terminal, browser and CLI clients over one protocol.

This is a **pre-release**. `brew`, `install.sh` and `leveler upgrade` all keep
serving the latest stable (`0.1.4`) unless you ask for the beta by name:

```sh
LEVELER_VERSION=v0.2.0-beta.1 sh -c "$(curl -fsSL https://raw.githubusercontent.com/dengmengmian/CodeLeveler/main/install.sh)"
```

**macOS and Linux only.** There is no Windows binary in this beta — see
[Platforms](#platforms). Windows users stay on stable `0.1.4`, which does ship
one.

## Included

- **Persistent coding runtime.** One engine; clients attach and detach without
  ending the work.
- **TUI.** The primary surface: themes with contrast gates, session menu,
  approval flow, live tool and diff rendering.
- **Web client.** `leveler web` against the same local runtime, sharing the
  generated client protocol rather than a parallel implementation.
- **CLI workflow.** `leveler run` / `resume` for scripted and one-shot use.
- **Sessions and resume.** SQLite-backed: conversation, pending approvals, tool
  results, diffs and verification state survive a restart.
- **Permissions.** Typed tools, approval policies, standing rules, workspace
  boundaries, and `leveler trust` for in-repo configuration.
- **Sandbox-aware execution.** Seatbelt on macOS, bubblewrap on Linux, Job
  Objects with AppContainer and ACL restriction on Windows.
- **Verification workflow.** The agent runs the project's own checks and its
  completion verdict is judged against them, not against its own summary.
- **`!command`.** Run a shell command in the repository without invoking the
  model — live output, per-command stop, same sandbox as agent commands.
- **Secret propagation safety.** Tool output crossing the model boundary carries
  no secret values while keeping keys and structure intact.

## Known limitations

Stated, not hidden. Each is measured, not suspected.

- **Delegation is opportunity-based.** The runtime executes a delegation
  reliably whenever the model elects to collaborate. It does **not** promise
  that the agent splits a task on its own, and it does not force one. Measured
  adoption on qualified tasks is 10–30 %; eight hypotheses were eliminated and
  the cause is not in CodeLeveler. Ownership safety, claim/settlement and
  durable provenance are Beta-ready.
- **Windows has no daemon socket transport.** Sessions and `resume` work.
  `leveler serve`, `web`, `remote projects` and `remote agent` refuse with a
  clear message instead of failing obscurely. A *confined* Windows command
  delivers its `!command` output on completion rather than streaming live.
- **No Windows binary in this beta.** Three Windows tests fail on `main` —
  `command_delivery`, `user_shell`, `side_effect_barrier_test` — so the artifact
  is built but not published rather than handed out with a red suite. The
  Windows job compiles, lints, and passes its security canaries (NTFS junction
  behaviour, AppContainer ACLs, Job Object descendant termination). Two of the
  three failures point at what AppContainer actually permits and need a Windows
  machine to answer; three rounds of remote inference fixed nine of twelve
  failures and then stopped buying anything. macOS, Linux, supply-chain audit,
  web and mobile jobs are green.
- **Long-running goals will improve.** A child does not survive a restart today:
  a resumed run reports it lost, releases its scopes and asks the model to
  re-delegate. Durable child sessions are designed, not shipped.
- **Structured sub-agent workflows are post-Beta.** Delegation Advisor,
  `SubAgentProvider`, background-first supervision UX and capability negotiation
  are on the roadmap behind the Beta gate, deliberately.
- **Binaries are not notarized (macOS) or code-signed (Windows).** First run may
  need one manual approval; the README says exactly which.

## Publishing checklist

The tag builds all four targets into a **draft**. Publishing is manual, and one
of its steps is manual on purpose:

1. Wait for the `Release` workflow to finish all four build jobs. A build
   failure on any target is a stop — including Windows, whose *build* is
   expected to pass.
2. **Delete `leveler-v0.2.0-beta.1-x86_64-pc-windows-msvc.zip` and its
   `.sha256` from the draft's assets.** This is the only thing standing between
   the decision above and a Windows binary going out anyway. The workflow does
   not do it, because a later beta may well want Windows back.
3. Confirm the release is marked **pre-release** (the workflow sets it from the
   `-` in the tag; verify rather than assume).
4. Paste this file's content as the release body, above the auto-generated
   commit list.
5. Verify the install path a user would take, on both published platforms:
   `LEVELER_VERSION=v0.2.0-beta.1 sh -c "$(curl -fsSL …/install.sh)"`, then
   `leveler --version` and `leveler doctor`.
6. Confirm the channel actually split: `releases/latest` still resolves to
   `v0.1.4`, and a bare `install.sh` run installs `0.1.4`, not the beta.
