# CodeLeveler v0.2.0-beta.2

The second public beta. Same runtime as `beta.1` — its architecture was frozen
before that release and nothing here reopens it — with the product work that
the first beta's own report deferred: an interface that says one true thing at
a time, a first run that tells you what to fix, and observation you can read
without opening SQLite.

This is a **pre-release**. `brew`, `install.sh` and `leveler upgrade` all keep
serving the latest stable (`0.1.4`) unless you ask for the beta by name:

```sh
LEVELER_VERSION=v0.2.0-beta.2 sh -c "$(curl -fsSL https://raw.githubusercontent.com/dengmengmian/CodeLeveler/main/install.sh)"
```

**macOS and Linux only.** No Windows binary, unchanged from `beta.1`.

> ### If you are on `beta.1`, install this one by name
>
> `beta.1` shipped with a version comparison that ignored the `-beta.1` suffix,
> so it reads itself as `0.2.0` and `leveler upgrade` will never offer you
> anything. **That is fixed here** — this binary keeps its pre-release suffix
> and reports itself correctly — but the fix is in the *new* binary, so it
> cannot help the old one reach it. Re-run the `LEVELER_VERSION=` line above.
>
> Still do not run `leveler upgrade --force` on `beta.1`: "latest" is stable
> `0.1.4`, and `--force` skips the newer-than check and downgrades you.

## What changed

**The interface speaks one language and counts one clock.** The turn-end
summary was assembled from hardcoded literals — `1 files` and `verify ✓` in
English beside `计划 5/9` in Chinese — so both locales saw a mixed line, and a
single changed file was reported in the plural. A running command printed its
own elapsed and the turn's next to each other with nothing to tell them apart
(`运行 cargo test --workspace · 2m 17s · 0s`). Both are fixed, and the elapsed
now belongs to whatever owns it.

**A first run tells you what to set.** With the provider's key variable unset,
`leveler run` used to send the request anyway and hand you the provider's
reply: advice about an `Authorization` header, naming no variable and no
command — printed three times, because every layer of the error chain quotes
its source. A run now refuses before its first request:

```
provider `deepseek` has no API key: $DEEPSEEK_API_KEY is not set
    export DEEPSEEK_API_KEY=<your key>
    leveler login deepseek
```

**`leveler trace` reports what a session cost and who spent it.** Duration,
cached input tokens, cost, the verification verdict, and a split between the
root session's spend and its child agents'. A figure nobody measured reads
`UNAVAILABLE`, never `0`. On the way, a real accounting bug: the request list
is capped at 200 rows for display, and the token totals were being computed
over the capped list — so a session past 200 model calls reported the spend of
its last 200 as the whole session's.

**A workspace map in the first request.** Landed before this release as part of
the round-trip work; it removes the exploratory round trip that used to be
spent discovering what the repository contains.

## Known limitations

These are measured, not guessed.

- **Model and provider latency dominate.** Across 13 runs and 6,296 seconds,
  93.5% of wall clock is waiting for the model, 6.4% is tool execution, and
  0.1% is CodeLeveler itself. If a task feels slow, the runtime is almost never
  why.
- **Reasoning effort is expensive.** On a controlled medium task, `max` and
  `high` produced the same round count, the same token volume and the same
  correctness — and `max` took 3.5x the wall clock, all of it inside one
  pathological round per run. This repository's own `configs/` bundle still
  ships `default_effort: max`; if you copy those model files, consider `high`.
  The effect does **not** reproduce on long real-repo work, where wall clock
  tracks round count instead.
- **Honest refusal is not reliable.** Given a task that contradicts a
  maintained test, CodeLeveler refused honestly in 4 of 6 measured attempts and
  claimed success in 2. The two competitors measured alongside it did worse,
  but 4 of 6 is not a guarantee: read the diff before you trust a success
  claim on an ambiguous ask.
- **Some models never batch tool calls.** The executor runs independent
  read-only calls concurrently, but a model configured with
  `max_parallel_tool_calls = 1` never emits them together, so exploration stays
  serial.
- **Long-task trajectory is model-dependent.** The same case at the same
  settings ran 46 rounds once and 60 another. Budget by outcome, not by rounds.
- **Multi-agent delegation does not trigger on its own** in ordinary work. No
  child agent spawned in any run of this closure.
- **A resumed session does not say the tree already changed.** The prior diff
  is in the session and on the Diff screen, but the default view gives no hint
  that a file is already modified.
- **A wrong API key** reports the provider's own "Incorrect API key provided."
  without naming which variable it came from.

## Platforms

macOS (arm64, x86_64) and Linux (x86_64). Windows stays on stable `0.1.4`,
which does ship a Windows build, until its three failing tests are diagnosed on
a real Windows machine.
