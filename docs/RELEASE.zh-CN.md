# CodeLeveler 1.0.27

[English](RELEASE.md) · [历史版本](../CHANGELOG.zh-CN.md)

本版让跨会话记忆默认开启：运行时会话结算后捕获持久事实，整理为 Markdown 主题，并在后续会话中向模型提供有界的主题索引。记忆不阻塞回合，也从不决定 Agent 的下一步动作。本版同时按需求种类明确完成证据策略，把后台验证绑定到它实际运行的工作区版本，让被阻塞的 Goal 与模型自己的未完成计划对账，并修复资质验证中发现的 Windows 输出解码、捕获生命周期与依赖问题。

- **跨会话记忆默认开启。** 未写 `[memory]` 时解析为 `rollout = "active"`，显式 `rollout = "off"` 才关闭；`record_only` / `shadow` 用于分阶段放量。只有 `active` 会把记忆暴露给模型，`off` 不打开数据库、不创建目录。工作区身份取自 git remote，因此同一仓库的两个克隆共享记忆，而临时工作目录没有工作区作用域。所有数据位于 `<LevelerHome>/memory/`，不写入仓库。
- **捕获是持久且异步的。** 每个已结算回合后，运行时把该会话尚未捕获的范围排入队列。抽取作为后台任务运行，持有五分钟租约并强制使用工具调用，产出结构化 observation 的 Markdown 文件与 SQLite 账本行。捕获不触碰对话、不阻塞回合；记忆失败在用户工作已经成功之后以活动状态报告。结果提交是幂等的。
- **重启与退出不丢工作。** 正常退出把进行中的捕获释放为可重试，且不消耗有限的失败预算；下一次启动扫描工作区队列并恢复可认领的任务，不回填历史回合。会话暂停或全局 `off` 会记录被跳过的回合，重新启用记忆时不会补抓。崩溃进程的任务等待租约到期，不会被其他进程抢占。
- **Dream 只有一个所有者。** Dream 读取待处理 observation，创建或更新 Markdown 主题。`memory_state.sqlite` 中的持久行以六小时租约跨进程串行化整理；所有者 PID 已消失的租约视为过期。自动 Dream 在捕获结算后运行，`/dream` 运行单次整理，`D` 运行受调用数与字节预算约束的批量整理。
- **读取与管理。** 每回合的提示词收到有界的 `## Cross-session memory` 索引，列出主题路径与一行描述；Agent 用普通 `read_file` 读取主题。没有独立检索 API，也没有向量数据库。`/memory` 现在是覆盖在对话上的居中 Overlay：Global 与 Workspace 合并在同一列表，右侧实时 Markdown 预览，支持搜索与 `Ctrl+F` 全屏，阅读、过滤、刷新、暂停与 Dream 操作保留；`leveler memory status|show|remember|forget` 提供 CLI。忘记绑定 `memory show` 打印的精确 BLAKE3 哈希：先写 tombstone，再删除文件，并从索引、捕获与整理中排除该路径。保留的 archive 对 Agent 文件工具不可见，被忘记的事实无法从中召回。
- **记忆配置修改即时生效。** `memory` 与 `memory_model` 是真正的配置维度：只改记忆配置也构成 generation 变化，重载发布刚解析出的配置而不是上一版，因此 `/memory` 与捕获决策不再继续读取启动时的 rollout。
- **被阻塞的 Goal 必须与计划一致。** 模型自己最新的显式计划仍列出从未标记完成的步骤时，`blocked` 结案会被拒绝一次；拒绝会列出未完成步骤与所有结构化出口，确认后的阻塞会被接受，冲突保留在回执中。该检查每个驱动周期最多一次，永不把阻塞改写为完成，也永不代替模型把待办步骤标记为完成。
- **完成证据按需求种类给出明确策略。** `named` 交付项属于模型判断：已交付的 `done` 记账记录为 `reported`，正常完成，不再产生「没有机械检查」警告。`tests` / `command` 需求只由精确声明的命令、且同一命令最新的一次执行记录满足；不同命令或复合命令行不是它的记录。对 `tests`，`verified` 表示声明的命令在最后一次变更之后执行并以 0 退出，不表示该命令真的执行了测试。需要 Runtime 无法取得的证据的需求仍为 `unverified`，并保留真实警告。
- **后台验证绑定到它实际运行的工作区版本。** Runtime 在真实执行边界采样一次变更计数器，执行结束时再采样一次，并把两者写入持久化的 `CommandExecutionVersions` 行。通过运行只有在启动版本与结束版本相同、且不早于完成判定时的当前版本时才成立；后台测试以 0 退出、但运行期间模型继续改代码时，执行成功是真实事实，但不能证明当前工作区。在同一版本上重新运行即可正常完成，旧运行保留真实退出状态但不能声称版本一致。
- **后台变更记账不再依赖结果消费路径。** 任务的结算变更集成为持久化终态事实的一部分，并且每次执行只推进一次工作区版本：自动投递通知、`wait_task`、`get_task` 读取同一个执行事实。失败或被停止但确实修改了文件的任务仍然计入；没有改动的任务不产生虚假 mutation；重复读取不会重复推进版本。
- **工具输入错误会被点名。** `shell_command` 拒绝与 `cmd` 并列或替代 `cmd` 的 `program`、`args`、`command`，会指出类型错误的 `cmd`，被拒绝的调用不会执行。`reason` 等描述性字段与文档化的 `workdir` 别名保持可用。
- **计划进度有独立状态行并原地更新。** 运行中的计划持续显示在 TUI 状态区域，而不是只在步骤变化时出现一次。
- **Windows 子进程输出改为增量解码。** 跨管道分片的多字节字符保持为一个字符，后台日志使用同一解码器，被截断的 GBK 结果不再把保留的头部变成替换符。TUI 完整输出优先读取原始捕获旁的 UTF-8 展示副本；原始 stdout/stderr 捕获文件仍保持逐字节精确。
- **未真正启动就失败的用户 Shell** 会把宿主拒绝原因显示在实时视图中，而不只在重连后的记录里可见。
- **后台任务展示更安静。** 启动任务不再在工具行之外重复弹出提示；失败只作为对话记录与后台任务页里的记录，不再产生需要确认的底部提醒。运行计数单元只统计当前仍在运行的任务。
- **子代理嵌套受栈约束。** 子代理 run future 被装箱，轮询嵌套状态机不再为每一层嵌套多消耗一个完整栈帧。
- **评测归因。** 被运行时按明确原因拒绝的完成声明会连同该原因记录，不再被记为运行时 Gate 失败；一次运行按其轨迹判定。
- **依赖。** `quinn-udp` 0.5.16 关闭 RUSTSEC-2026-0538。
- **工程。** 新增 GitHub issue forms。

安装包是命令行程序，包含 macOS（Apple Silicon 与 Intel）、64 位 Linux 和 64 位 Windows。没有 Linux ARM 安装包。桌面客户端可从源码构建，不在本安装包内。安装包不含 Apple 公证或 Microsoft 签名。
