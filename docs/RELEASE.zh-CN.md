# CodeLeveler 1.0.16

英文版：[`RELEASE.md`](RELEASE.md)

本次发布让卡住的模型响应变得可诊断、可恢复，并定下会话展示方式：工具活动在
每个可见阶段累积为一条回执，思考只出现在状态栏，详情按需展开。
Web 与 Desktop 不在本次发布的验收范围内。

## 模型响应

- 响应体读取失败时，记录传输层当时已经看到的事实——HTTP 状态、声明的 content type 与 encoding、已读字节数、脱敏后的尾部片段——写到失败请求下，`leveler trace` 会打印。`200` 之后 body 损坏，不再和“上游从未作答”无法区分。
- 失败文案跟随投递证据：请求未发出时才是“无法连接模型服务”；已收到响应头后是“接收模型响应失败”；流中途被切断是“模型响应接收中断”；传输层无法判断时为“与模型服务通信失败”。
- 没有答案文本与工具调用数据、仅产生推理的瞬时中断，可以使用有界重试生命周期。推理仍是已生成（且可能已计费）的内容，因此该失败保持 `Caution` 而不会变成“可盲目重放”；每次失败尝试先结算，重试不会合并被丢弃的推理；已有答案文本或已开始的工具调用依然绝不重放。

## 执行

- 死掉的宿主会留下 ready 文件。活性现在由宿主自己的生命周期锁判定，而不是文件是否存在：死者残留会被清理，runtime 能正常启动，不再以 `Connection refused` 失败。
- 执行宿主收到 SIGTERM 时干净退出，与空闲退出走同一条路径删除 ready 文件。
- 宿主从未接纳的语义写保留会在下次启动时释放——仅当归档中没有该任务的事实、且没有未决的 spawn intent；其余情况一律保留。也可以用 `leveler background journal list` 与 `leveler background journal abandon <task-id>` 手动查看与释放。

## 展示

- 连续普通工具在同一可见阶段内累积为一条回执，单个工具也算一条。收起时头部报告真实种类与次数、单独标记失败，并说明运行中调用自己的状态与数量；折叠不会把运行中或已取消的工作画成已完成。
- 思考不再出现在会话中。状态栏报告流式事实并在完成时清除；Ctrl+O 打开最新工具组的详情，不会退而打开某条思考。
- 工具与失败详情默认收起，通过各自的头部展开。
- 已确认的编辑 Diff 默认完整展示；进度文本与最终回答按原文展示，不再每段加前缀符号。

## 修复

- 权限设置编辑不再把观察到快照之后的回答进度当作设置冲突。
- Agent 的过程更新把观察到的工作与目标连接起来，而不是逐条复述工具调用。
