# CodeLeveler 1.0.25

[中文](RELEASE.zh-CN.md) · [Version history](../CHANGELOG.md)

This release adds durable scheduled automation, deterministic native actions, computer use, and continuation of local Claude Code and Codex sessions. Submitted input is now journaled across reconnects and restarts.

- **Scheduled automation:** `leveler schedule` and the TUI `/schedules` page create durable definitions that run a shell command, a typed native action, or an ordinary agent goal. Triggers are a one-off RFC 3339 instant, a fixed interval, a daily time, selected weekdays, or a five-field cron expression, evaluated in an IANA timezone. A definition names its workspace, permission profile, session policy, overlap policy (`skip-if-running`, `queue-one`, `allow-concurrent`), misfire policy (`skip`, `run-once`), timeout, and grant. A claim is leased: an expired lease settles the run as `unknown` and is never retried. `add`, `list`, `show`, `update`, `grant`, `revoke-grant`, `runs`, `pause`, `resume`, `run-now`, `cancel` and `remove` manage definitions; `dispatch` runs one pass and `serve` is the resident dispatcher. The `schedule_inspect` and `schedule_manage` tools give the model the same facts, and the Web and desktop Automation pages read the same runtime state.
- **Unattended authority:** an unattended run needs a persisted grant that covers its action, workspace, trigger, permission profile and external-side-effect choice. Changing a covered field invalidates the grant. Full permission does not replace it, and a missing grant refuses the action before it starts rather than prompting with nobody present.
- **Operating-system wakeups:** `schedule enable` registers a launchd agent on macOS or a per-user Task Scheduler task on Windows; `disable` and `uninstall` remove it; `status`, `wakeups` and `doctor` report the registration, wake history and diagnostics. Linux reports the wakeup backend as unsupported; a schedule can still run through `schedule serve` or `schedule dispatch`.
- **Native actions:** `leveler native capabilities` probes Mail on macOS or Outlook on Windows without launching the application, requesting permission or sending anything. `leveler native action` executes `mail.draft.create`, `mail.send.open_ui`, `mail.send.submit` or `mail.sent.check` deterministically with no model, daemon or session. Input is validated before planning, user text reaches the application through private `0600` files rather than argv or script source, and success requires a recognized result marker. A timeout or unrecognized outcome is `unknown` and is never retried. The model tools are `native_capabilities`, `native_action` and `native_verify`.
- **Computer use:** `computer_observe` and `computer_act` expose desktop observation and control through macOS Accessibility and CoreGraphics or Windows UI Automation and Win32. Observation references are scoped to the session and revalidated against the live UI before every action. The tools use the existing approval policy, capability packs and image channel; they do not add a second execution path. macOS requires Accessibility and Screen Recording permission, reported as a call-time fact.
- **Foreign sessions:** `/resume-claude` and `/resume-codex` list local Claude Code or Codex sessions (or accept a session id) and import one into a native CodeLeveler session seeded with a bounded briefing. The source store is read-only and remains the authority for the original history. The briefing quotes the task and the state the source ended in instead of copying the transcript; tool calls are never replayed, a workspace mismatch is reported before the import, and `foreign_session_history` reads the source on demand.
- **Durable input:** a submission made while a turn is running is journaled with its identity before admission. Reconnects and recovery use that record to deliver the submission once instead of losing it or sending it twice. A final answer is bound to the model's explicit `deliver_answer` declaration and persisted before the turn ends, so a crash after the answer does not make another model call.
- **TUI:** code blocks and diffs share one syntax highlighter, and an applied diff is one copyable document rather than a patchwork of separately colored rows. `/schedules` manages definitions in place; `/resume-claude` and `/resume-codex` open the foreign-session picker.
- **Fixes:** a client that loses the runtime startup race now adopts the live runtime instead of failing permanently; a natural recurring rule keeps its own grid while a shell run is still active; `allow-concurrent` shell runs get one execution context per run; a one-off keeps its pending occurrence when its trigger is rescheduled; `schedule show` no longer advertises a completed, cancelled or missed occurrence as the next run; the headless CLI prints the committed delivery instead of a bookkeeping round.

The release archive is the command-line program for macOS (Apple Silicon and Intel), 64-bit Linux, and 64-bit Windows. There is no Linux ARM archive. The desktop client can be built from source and is not in this archive. Packages are not Apple-notarized or Microsoft-signed. Existing configuration remains usable.
