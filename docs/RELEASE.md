# CodeLeveler 1.0.26

[中文](RELEASE.zh-CN.md) · [Version history](../CHANGELOG.md)

This release makes goal continuation, scope changes and completion evidence model-declared and runtime-validated. Questions survive disconnects and restarts, provider outages are recovered inside one logical request, project-rule delivery is auditable, and the legacy mobile client has been retired.

- **Declared intent, not wording.** Continuation, pause, amendment, cancellation and questions are decided by the model in the running turn. `declare_intent` quotes the newest user message verbatim; the runtime checks that the quote came from that message, which goal it targets, the legal ordered operations, and the plan step a boundary names by stable id. It refuses to guess when several goals are running and none is named. Any language, phrasing or compound instruction uses the same path, and no extra classification call is made. A pause is released only by a validated `continue_task`.
- **A goal scope you can audit.** `commit_task.requirements` and `declare_scope` make the acceptance set structured and model-declared. Each change is anchored to a verbatim quote, stored as an ordered durable event (migration 0055), and projected by `get_goal_scope`. The keyword, negation-word, section-heading, quantifier and test-name heuristics are gone; user text is interpreted only by the model.
- **Evidence, not a success claim.** `update_goal(verification)` remains the model's declaration; the completion gate resolves it against the runtime's own execution record by call id, exact command line, or command plus a note. A failed, stale or contradicted run is refused for that reason, and a combined pass whose component later failed on its own does not survive. An accepted completion persists a structured `VerificationReport`, and `Verified` cannot exist without a requirement-level record. A passing command proves an execution, not a delivered requirement.
- **Durable questions.** A clarification has an id, structured questions and an answered/skipped/cancelled terminal in the event log. The live waiter is only a delivery channel, so a client disconnect, a daemon restart or a task cancellation no longer loses the question or lets a late answer start cancelled work. The first terminal wins, duplicate or stale answers are refused, and the pending card is restored from durable state.
- **Continuity across windows.** Checkpoints carry answered clarifications, amendments, verbatim user messages, runtime-observed command outcomes and the window's own accepted outcome. The plan is projected from the newest declaration, so a yielded window no longer repeats work its predecessor finished.
- **Provider outages.** One logical request now recovers from transient provider failures: `[retry]` defaults to 12 retries after the first attempt inside a 600 s window, backoff climbs to a 60 s steady rate, and `Retry-After` wins. A retry after a tool result does not repeat the side effect, and the TUI says "model service unavailable · retry" instead of reporting a lost connection.
- **Project rules.** Rules are read once per turn and delivered with a typed audit. Unreadable, invalid-UTF-8, non-file and symlink-escaping sources are reported instead of silently dropped; empty, absent and loaded sources stay distinguishable; a mutating call pauses when an applicable scoped rule cannot be read; a directory's own `AGENTS.md` is scoped to it.
- **TUI truth.** Tabs and control bytes are normalized at the composer and Markdown boundaries before width measurement, so pasted input or model Markdown cannot ghost later cells. The splash deletes its Kitty image data before leaving the alternate screen.
- **Retired.** The standalone Flutter mobile client, its relay, and the host-side remote protocol/agent crates that served it are removed. The CLI and TUI no longer have paired-device commands or screens; the local transport, runtime host and client command/event/snapshot protocol remain the native session interface for other clients.
- **Dependencies.** `rmcp` 3.9.0 closes RUSTSEC-2026-0462; `cap-primitives` 4.0.3 closes the sandbox escape in RUSTSEC-2026-0482; `rustix` 1.1.6 closes RUSTSEC-2026-0486. RUSTSEC-2026-0459 (bundled SQLite in `libsqlite3-sys`) has no fixed `sqlx` 0.8 release, so it is recorded with an expiry and a local-file reachability boundary instead of being silently ignored.

The release archive is the command-line program for macOS (Apple Silicon and Intel), 64-bit Linux, and 64-bit Windows. There is no Linux ARM archive. The desktop client can be built from source and is not in this archive. Packages are not Apple-notarized or Microsoft-signed.
