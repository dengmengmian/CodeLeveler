# CodeLeveler 1.0.28

[中文](RELEASE.zh-CN.md) · [Version history](../CHANGELOG.md)

This release makes project trust and skills operable from the terminal, loads `AGENTS.md` as standard project context, unifies every independent TUI page on one design system, and hardens runtime retirement and execution ownership.

- **Trust is a TUI surface.** `/trust` lists all, untrusted, trusted and changed definitions over the same store and discovery the CLI uses; it shows the content, the displayed SHA-256, the approval version and the approved-to-current diff, and approves one or many marked rows or revokes a record. The page never sends a command to the model and never runs the CLI through a shell. A running `load_skill` for an untrusted skill raises a typed allow-once / trust-this-content-version / deny request, and the same tool call continues after the decision. Allow-once writes no record; a denial is remembered for that identity and digest for the session; a disconnected or cancelled wait refuses safely instead of hanging. FullAccess adopts only rule and skill bytes captured in the session-creation baseline taken before the first model call; an edit after the baseline, a resumed session without provenance, and every declarative agent definition still need a persistent approval.
- **`AGENTS.md` is default project context.** `AGENTS.md` at any depth now loads in Auto, Restricted and Full without a trust approval, including first creation, an edit, `git pull`, a config change, a resume and a nested scope. It is context, never authority: it cannot grant shell, network, filesystem or external-path permissions, change the permission mode, write, approve or revoke a trust record, or make another definition trusted. The loader still enforces the contained regular-file, UTF-8 and symlink boundary. The trust gate remains for `.leveler/instructions.md`, `.leveler/rules/*.md`, declarative agents and skills. Existing `AGENTS.md` trust records are preserved but are no longer consulted, and startup no longer prints definitions or a trust hint.
- **Skills are a first-class surface.** `/skills` is one read model over the same registry the runtime, the `$` popup and `load_skill` use: available, disabled, untrusted and invalid states, search and filtering, a detail view with provenance and invocation flags, and durable enable/disable through `state/skills.toml`, with project disables keyed by the canonical project root. A skill is invoked as `/name [args]`, or `/scope:name [args]` when its name would capture a built-in command. Every turn records which skills were indexed, selected, loaded and refused, without a body or a filesystem path. `load_skill` and explicit invocation verify the package and deliver a reference manifest; during that turn `read_file` can page a listed reference from the exact verified package, while ordinary path reads of `SKILL.md` and unbound references remain refused.
- **One design system across the terminal UI.** The 28 independent pages now share one modal workspace with consistent geometry, title, footer, focus, mouse routing and page-level list navigation. List pages share one row, selection and hover model; split pages adapt below their wide layout; document pages take the full available height; the output viewer windows large file-backed content; Memory and BTW keep their own surfaces but use the same visual language. Completed replies offer `[Copy Markdown]` and `[Copy Text]`. Checkpoint restore after recovery now shows the rolled-back conversation consistently, and a corrupt recovery snapshot no longer reads as an empty candidate.
- **Runtime lifecycle and ownership.** A Unix IPC connection that never sends a request can no longer hold graceful shutdown and idle eviction open. A newer build waits for a legacy or busy runtime to exit safely instead of failing startup. `leveler runtime status` reports the workspace runtime's identity, build, work counts and idle-eviction state, and `leveler runtime stop` retires it only when no work would be interrupted, with a reason and a nonzero exit when it cannot. A user shell's terminal event is published only after its durable ownership token is released, so the composer can no longer accept input into a session that still holds an active turn. `leveler background logs` for a hosted task reads the hosted record instead of printing an empty inventory tail.
- **Behavior changes and upgrade notes.** `AGENTS.md` no longer needs an approval; old records remain on disk but are ignored. An untrusted skill is still not loaded without a decision, but `load_skill` now asks instead of silently skipping it. Reading a skill reference through `read_file` is limited to the exact package version delivered in that turn. `leveler runtime` upgrade handoff is unchanged for 1.0.28 and later clients: a runtime started before 1.0.28 does not speak the access-token handshake, so let it finish its work and exit normally once before starting this version; the client never signals it or steals the endpoint.
- **Known limits.** This cycle verified macOS with a real PTY, Terminal.app, a real provider and real tool execution; Windows Terminal/ConHost, Linux desktop terminals and non-macOS IME were not available and are **NOT_VERIFIED** here. CI builds and smoke-tests the archive on macOS (Apple Silicon and Intel), 64-bit Linux and 64-bit Windows. On Windows, a confined shell can still create a previously missing `AGENTS.md`, and that file will then be read as project context; it still carries no authority, and existing protected objects keep their OS fences. `.leveler` definitions created that way are never admitted without approval. FullAccess remains a user-authority boundary rather than an OS guarantee. Packages are not Apple-notarized or Microsoft-signed.

The release archive is the command-line program for macOS (Apple Silicon and Intel), 64-bit Linux, and 64-bit Windows. There is no Linux ARM archive. The desktop client can be built from source and is not in this archive.
