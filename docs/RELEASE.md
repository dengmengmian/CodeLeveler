# CodeLeveler 1.0.27

[中文](RELEASE.zh-CN.md) · [Version history](../CHANGELOG.md)

This release makes authority-bearing project definitions inert until a person approves their exact bytes, puts a credential boundary around the local runtime control socket, and adds one workspace for running work and diagnostics. Reviews now run as a native, evidence-driven child, sessions gain titles, reversible archive and grant control, and goal identity survives restarts and context folds. Release archives move to xz, and the legacy browser UI is retired.

- **Project definitions are inert until trusted.** `AGENTS.md` at any depth, `.leveler/instructions.md`, `.leveler/rules/*.md`, declarative agents under `.leveler/agents`, and skills under `.leveler/skills` and the compatible project roots are admitted only after a human approves their exact bytes. `leveler trust` lists pending definitions and approves the SHA-256 it displays; `leveler trust show`, `diff` and `revoke-definition` manage the record. Editing, `git pull`, a commit, a restart or a resume does not inherit an old approval. Unapproved definitions never enter the model's control context; the next turn receives a diagnostic naming the path and its state. The trust store lives outside the workspace and fails closed when missing, corrupt or inside the repository. A skill's approval covers `SKILL.md` plus its whole `references/` tree; `load_skill` returns the verified text and restricted file tools refuse direct path reads of that content.
- **The local control plane is credential-gated.** The Unix runtime socket requires a per-runtime random token in addition to its `0600` mode; the token is `0600` in a `0700` directory, hidden from confined commands and, on Linux, the server refuses peers outside the runtime's mount namespace. `ManageSchedule` is trusted-local-only over TCP. Windows keeps its named-pipe ACL boundary, and FullAccess remains the documented user-authority boundary.
- **Execution authority follows the grant.** A standing Allow rule or automated reviewer answers whether a call may run but keeps the profile's resource scopes; exact-call consent no longer clears an explicit `--deny-network`. Unknown permission-rule keys are rejected instead of silently dropping a constraint, wildcard paths stay session-only, credential names compare ASCII-insensitively, and shared model budgets reserve in flight per request.
- **`/tasks` is a workbench.** It aggregates the current goal, child agents, background tasks and reviews, schedules and their last runs, and every durable session. Active / Recent / All share one selection; `x` cancels a current-session task through the runtime; `r` re-reads live sources.
- **`/doctor` is structured diagnostics.** Every check is a finding with a stable id, a typed status, observed evidence and an optional existing action. `UNKNOWN` and `NOT CHECKED` never render as a pass, live MCP state is explicitly not checked, and `leveler doctor --json` prints the same report.
- **`/review` 1.0.** A review is manual, read-only and evidence-driven: the current delivery, the working tree, the project, a session, a commit, a branch base or explicit paths. The reviewer runs as an independent child with its own id, budget, cancellation and durable report. A Lead Reviewer can launch read-only investigations; candidate findings are attributed and only adopted findings count as formal defects. Reports are complete revisions bound to the evidence revision they saw, and a later change marks them stale. Automatic review is retired; a legacy `independent_review: required` no longer starts one.
- **Sessions, output and permissions.** Titles are separate from the verbatim goal request; archive is reversible; `leveler permissions grants` lists and revokes resource grants; delete refuses live work. `/model <ref>` switches only the current session and `/model default <ref>` changes the global default; `/permission` applies immediately. Large tool output opens through `/output tool [id]`, `/copy N` selects a complete answer, `/export` appends a tool-evidence section, and checkpoint restore requires a second confirmation that names the rollback.
- **Goal identity and completion evidence are stable.** Several deliverables are multi-step work, the adopted objective is rebound rather than duplicated through crash recovery and fold, and the pre-dispatch crash window is covered. Completion evidence matches the argv that actually ran, including a run cited by its display label. A requirement's mechanical kind is frozen once owed; new words can lower a requirement but not silently raise it; the terminal summary the schema promises is required.
- **The TUI.** Transcript search with turn navigation, running-work protection on exit, rebuilt MCP / project-settings / help pages, terminal-device reply isolation, bidi neutralization in snippets, and inline localized feedback for legacy commands.
- **Daemon and runtime.** The access token is published before the socket endpoint and the ready file is written atomically; a startup stress gate holds that contract. A turn after a restart reads its context before acting, a first turn's own message is distinguished from prior work, model usage is recorded once per physical attempt, and private user data is owner-only on disk.
- **Platform.** Windows resource grants bind a stable volume/file id and creation time; commit and branch reviews read git objects without starting a `git` process; a persistent execution host shares write-root leases across processes; the schedule logon trigger is registered for the user. macOS and Linux archives move to `.tar.xz` (about 40% smaller); the `.tar.gz` sibling remains for older updaters.
- **Breaking changes.** The legacy Web UI and `leveler web` / `/web` are retired. Automatic review is retired. Existing single-file skill approvals re-appear as `changed` and need one re-approval. Permission files with unknown keys now load as a degraded rule set that asks instead of a broader Allow.
- **Known limits.** On Windows, a confined shell can still create a previously missing `AGENTS.md` or `.leveler` tree; it is never admitted without approval and existing protected objects keep their OS fences. FullAccess remains a user-authority boundary rather than an OS guarantee. Packages are not Apple-notarized or Microsoft-signed.

The release archive is the command-line program for macOS (Apple Silicon and Intel), 64-bit Linux, and 64-bit Windows. There is no Linux ARM archive. The desktop client can be built from source and is not in this archive.
