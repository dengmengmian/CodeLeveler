# CodeLeveler 1.0.27

[中文](RELEASE.zh-CN.md) · [Version history](../CHANGELOG.md)

This release ships cross-session memory on by default: the runtime captures durable facts after a turn settles, consolidates them into Markdown topics, and gives the model a bounded index it can read in later sessions. Memory never blocks the turn and never decides what the agent does next. The release also makes completion evidence explicit per requirement kind, binds background verification to the workspace version it actually ran on, reconciles a blocked goal against the model's own open plan, and fixes Windows output decoding, capture lifecycle and dependency issues found during qualification.

- **Cross-session memory, on by default.** An absent `[memory]` section resolves to `rollout = "active"`; `rollout = "off"` is the explicit opt-out, and `record_only` / `shadow` cover staged rollouts. Only `active` exposes memory to the model, and `off` opens no database and creates no directory. A workspace's identity is its git remote, so two clones of the same repository share memory, while a temporary working directory has no workspace scope. Everything lives under `<LevelerHome>/memory/`, never in the repository.
- **Capture is durable and asynchronous.** After every settled turn the runtime queues the ranges the session has not captured yet. Extraction runs as a background job with a five-minute lease and a forced tool call, and writes structured observations as Markdown files plus a SQLite ledger row. Capture never touches the conversation and never blocks the turn; a memory failure is reported as activity after the user's work already succeeded. Committing an outcome is idempotent.
- **Restarts and quits do not lose work.** A normal quit releases an in-flight capture as retryable without charging the bounded retry budget, and the next startup scans the workspace queue and resumes claimable jobs without enqueuing historical turns. A paused session or a global `off` rollout records the skipped turns, so re-enabling memory does not backfill them. A crashed process's job waits for its lease instead of being stolen.
- **Dream consolidates with one owner.** Dream reads pending observations and creates or updates Markdown topics. A durable row in `memory_state.sqlite` serializes consolidation across processes with a six-hour lease; a lease whose owner PID is gone is treated as expired. Automatic Dream runs after capture settles, `/dream` runs one pass, and `D` runs a bounded batch with call and byte budgets.
- **Reading and managing memory.** The prompt receives a bounded `## Cross-session memory` index of topic paths and one-line descriptions; the agent reads a topic with the ordinary `read_file` tool. There is no retrieval API and no vector database. `/memory` opens a centered overlay over the conversation with Global and Workspace in one grouped list, a live Markdown preview, search, `Ctrl+F` fullscreen, and read, filter, refresh, pause and Dream keys; `leveler memory status|show|remember|forget` covers the CLI. Forget binds to the exact BLAKE3 hash printed by `memory show`: a tombstone is written first, the file is removed, and the path is excluded from the index, capture and consolidation. The retained archive is invisible to the agent's file tools, so a forgotten fact cannot be recalled from it.
- **Memory configuration edits apply live.** `memory` and `memory_model` are real configuration dimensions: a memory-only edit is a generation change, and a reload publishes the freshly parsed bundle instead of the previous one, so `/memory` and the capture decision stop reading the boot-time rollout.
- **A blocked goal must agree with its plan.** A `blocked` resolution is refused once while the model's own latest explicit plan still lists steps it never marked completed. The refusal names the open steps and every structured exit; a confirmed block is accepted with the conflict kept in its receipt. The check is bounded once per drive, never rewrites a block into a completion, and never marks pending steps done on the model's behalf.
- **Completion evidence has an explicit policy per requirement kind.** A `named` deliverable is model judgement: a delivered `done` account completes as `reported`, without a "no mechanical check" warning. A `tests` or `command` requirement is satisfied only by a recorded run of the exact declared command that is also the newest matching execution; a different or compound line is not its record. For `tests`, `verified` means the declared command ran and exited 0 after the last change, not that the command executed tests. Requirements whose evidence the runtime cannot obtain stay `unverified` with their warning.
- **Background verification is bound to the workspace version it ran on.** The runtime samples the mutation counter at the real execution boundary and again when the execution ends, and records both on a durable `CommandExecutionVersions` row. A passing run counts only when its start and end versions are equal and at least the completion's version; a background test that exited 0 while the model kept editing is a real success but not evidence for the current tree. A rerun on one version completes normally, and legacy runs keep their exit status without claiming consistency.
- **Background mutation accounting is path-independent.** A task's settlement change set is part of its durable terminal fact and advances the workspace version once per execution, whether the result arrives through the auto-delivered notice, `wait_task`, or `get_task`. A failed or stopped task that changed files still counts; a task that changed nothing adds no mutation; repeated reads cannot advance the version twice.
- **Tool input mistakes are named.** `shell_command` refuses `program`, `args` or `command` used beside or instead of `cmd`, names a wrong-typed `cmd`, and never executes a refused call. Descriptive extras such as `reason` and the documented `workdir` alias keep working.
- **Plan progress has its own row and updates in place.** A running plan is shown continuously in the TUI status area instead of only at the moment a step changes.
- **Windows child-process output is decoded incrementally.** A multi-byte character split across pipe reads stays one character, background logs use the same decoder, and a truncated GBK result no longer turns its retained head into replacement glyphs. The TUI full-output pager prefers the UTF-8 presentation copy beside the raw capture; the raw stdout/stderr capture files remain byte-exact.
- **A user shell that fails before it spawns** shows the host's refusal in the live view, not only in the reconnected record.
- **Background task display is quieter.** Starting a task no longer posts a second notice next to the tool row, and a failed task is a record in the conversation and the jobs page instead of a footer reminder. The running-count cell counts only tasks that are running now.
- **Sub-agent nesting is stack-bounded.** Child run futures are boxed, so polling a nested state machine no longer costs another full stack frame per nesting level.
- **Evaluation attribution.** A completion claim the runtime refused for a named reason is recorded with that detail and is no longer booked as a runtime gate failure; a run is judged by its trajectory.
- **Dependencies.** `quinn-udp` 0.5.16 closes RUSTSEC-2026-0538.
- **Project.** Added GitHub issue forms.

The release archive is the command-line program for macOS (Apple Silicon and Intel), 64-bit Linux, and 64-bit Windows. There is no Linux ARM archive. The desktop client can be built from source and is not in this archive. Packages are not Apple-notarized or Microsoft-signed.
